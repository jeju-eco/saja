# 5호 ‘뭐 사야 하지?’ 설계

## 목표와 범위

혼자 쓰는 휴대폰용 장보기·위시리스트 웹앱. 이름 하나만 입력해 ‘사야 하지’ 또는 ‘사고 싶지’에 넣고, 구매·목록 이동·되돌리기를 손쉽게 한다. 저장 버튼, 계정, 서버, 가격 비교, 외부 쇼핑몰 연동, 알림은 첫 버전에 넣지 않는다. 기존 1~4호와 별도 프로젝트 및 배포 경로를 쓴다.

## 플랫폼·구조

정적 HTML/CSS/JavaScript PWA로 구현한다. 서버 없이 HTTPS 정적 호스팅에서 설치 가능하고 기본 화면·조작은 오프라인에서도 작동한다. 앱 셸은 서비스 워커로 캐시하고, 목록 데이터는 기기 내 IndexedDB에 저장한다. 첫 로딩·업데이트에는 네트워크가 필요할 수 있다. 외부 전송은 하지 않는다. 각 항목은 고유 ID, 이름, 목록(buy/want/done), 구매 전 목록(buy/want, 구매 완료 시에만), 생성·수정 시각, 선택적 메모·가격·링크를 가진다. 가격은 텍스트로 보관하여 통화·숫자 변환 오류를 피한다. 링크는 사용자 입력 URL만 열며 안전한 프로토콜만 허용한다.

## 화면과 동작

첫 화면은 ‘사야 하지’가 기본, ‘사고 싶지’와 ‘샀음’은 탭으로 전환한다. 입력창에 이름을 쓰고 해당 목록에 추가하면 즉시 영속화한다. 필수 필드는 이름뿐이다. 항목을 누르면 상세/수정 액션이 열리고, 별도 큰 버튼으로 구매 완료·목록 이동을 수행한다. 구매 완료 후 ‘샀음’에서 이전 목록으로 되돌릴 수 있다. 삭제는 확인 또는 짧은 실행취소 기회를 제공한다. 중복 이름은 서로 다른 항목으로 허용하되 같은 목록에서 중복 가능성을 알려준다. 빈 목록과 저장 실패를 명확히 표시한다. 탭·버튼은 휴대폰에서 한 손으로 누를 수 있게 넉넉히 둔다.

## 데이터 안전

각 조작은 IndexedDB 트랜잭션 성공 후 화면에 반영하고 실패 시 저장되지 않았음을 표시한다. 내보내기는 버전이 붙은 JSON 파일 다운로드, 복원은 해당 JSON을 검증하고 항목 수·영향을 미리 보여준 다음 사용자가 승인하면 적용한다. 기본 복원은 기존 데이터와 ID 기준 병합하며 ID가 같은 기존 항목은 보존하고 건너뛴 건수를 표시한다. 전체 교체는 별도 확인 후 한 트랜잭션으로 수행한다. 잘못된 파일·중복 ID·지원되지 않는 버전은 데이터 변경 없이 거절한다. 브라우저/기기 데이터 삭제 시 백업 파일이 없으면 복구할 수 없음을 명시한다.

## 검증 및 배포 기준

단위 테스트: 이름 정규화·목록 상태 전이·중복 안내·백업 스키마 검증·병합 충돌. 브라우저 통합 테스트: 추가 → 이동 → 구매 → 되돌리기 → 재시작 후 유지 → 내보내기/복원. 오프라인 재실행과 작은 휴대폰 화면을 실제 브라우저에서 확인한다. 배포 시 기존 앱의 경로/데이터를 건드리지 않고 새 정적 사이트 경로를 사용한다. 테스트 통과와 원격 접속·새로고침 확인을 구분해 보고한다.
